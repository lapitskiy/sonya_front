# Логи приложения на сервере

Приложение (`AppLog`) хранит кольцо из **последних 1000 строк** и раз в **15 сек** отправляет на бек только новые строки. Бек хранит последние 1000 строк на устройство.

Нужно, чтобы смотреть логи телефона без adb (например, BLE: scan / connect / disconnect).

## Базовый URL

Сервер в локалке (`192.168.0.50`), снаружи доступен по белому IP.

| Кто | Базовый URL | Зачем |
|---|---|---|
| **Телефон (app)** | `http://188.243.119.154:18000/` | отправка логов, как в `ApiService` |
| **Сервер / локалка / агент** | `http://127.0.0.1:18000/` или `http://192.168.0.50:18000/` | читать логи с машины, где крутится docker |

С самой машины сервера внешний `188.243.119.154` **не открывается** (нет hairpin NAT) — используй внутренний адрес.

Примеры ссылок для чтения (последние 200 строк):

- снаружи / в браузере: http://188.243.119.154:18000/debug/app-log?tail=200
- с сервера: http://127.0.0.1:18000/debug/app-log?tail=200
- из локалки: http://192.168.0.50:18000/debug/app-log?tail=200

## Читать логи

```bash
# База для curl с сервера (подставь BASE при необходимости)
BASE="http://127.0.0.1:18000"

# последнее активное устройство, последние 200 строк
curl "$BASE/debug/app-log?tail=200"

# конкретное устройство
curl "$BASE/debug/app-log?device_id=android-<ANDROID_ID>&tail=300"

# фильтр по подстроке (без учёта регистра)
curl "$BASE/debug/app-log?contains=SonyaFrontWatch&tail=300"

# список устройств, от которых пришли логи
curl "$BASE/debug/app-log/devices"
```

Параметры `GET /debug/app-log`:

| Параметр | Описание | По умолчанию |
|---|---|---|
| `device_id` | `android-<ANDROID_ID>`; если не указан — устройство с самым свежим приёмом | последнее активное |
| `tail` | сколько последних строк вернуть (1–1000) | 300 |
| `contains` | оставить только строки с этой подстрокой | — |

Ответ — `text/plain`, строки вида `2026-10-01 03:20:11.123 I/SonyaFrontWatch: ...`.
`404` — логи ещё не приходили или неизвестный `device_id`.

## Отправка (приложение → бек)

`POST /debug/app-log`

```json
{
  "device_id": "android-<ANDROID_ID>",
  "session": "<uuid процесса>",
  "lines": [{"seq": 1, "line": "2026-10-01 03:20:11.123 I/TAG: message"}]
}
```

- `seq` растёт внутри процесса, `session` меняется при перезапуске приложения; повторно присланные строки бек отбрасывает.
- При ошибке отправка повторяется с паузой (до 2 минут), строки не теряются, пока не вытеснены из кольца.
- Строки обрезаются до 2000 символов.

## Где код

| Что | Файл |
|---|---|
| Кольцо и отправка | `app/src/main/java/com/example/sonya_front/AppLog.kt` |
| Инициализация | `MainActivity.onCreate`, `VoiceRecognitionService.onCreate` |
| Бек | `~/sonya_back/assistant-backend/api/app/debug_log.py` (подключён в `main.py`) |

Отправка идёт отдельным OkHttp-клиентом без логирующего интерцептора и пишет только в `android.util.Log`, иначе отправка порождала бы новые строки в логе (петля).

## Ограничения

- Бек хранит логи **в памяти**: после рестарта контейнера `api` история пропадает.
- Эндпоинты **без авторизации**, как остальные на беке; в логах бывают тексты распознанных команд.
- В логах только то, что пишется через `AppLog`; системные сообщения Bluetooth-стека Android не попадают.
- После правок бека нужен перезапуск (код смонтирован томом, пересборка образа не нужна):
  `cd ~/sonya_back && docker compose restart api`.
