# Кнопка PWR (нижняя правая)

Как часы реагируют на кнопку PWR и как это устроено внутри, чтобы не наступать на те же грабли при следующей правке.

## Поведение (что видит пользователь)

| Действие | Результат | Кто это делает |
|---|---|---|
| Короткое нажатие (часы выключены) | Включение | Железо AXP2101, прошивка не участвует |
| Долгое нажатие 3-5 сек (часы включены) | Принудительное выключение | Железо AXP2101 (`PWRON` held low), независимо от прошивки |
| **Два коротких нажатия подряд** (≤600 мс между ними, часы включены) | Принудительное выключение **без** ожидания 3-5 сек | Прошивка (`pwr_button.c` + `watch_idle_off_force()`) |
| Одно короткое нажатие (часы включены) | Ничего (ждёт — вдруг будет второе) | Прошивка |

Длинное нажатие на выключение — это отдельная, полностью железная функция AXP2101 (удержание `PWRON` в low дольше порога само обрезает питание). Прошивка её не трогает и даже не обязана быть живой, чтобы оно сработало.

Короткое нажатие на **включение** — тоже чистое железо (PMU просыпается по фронту на `PWRON`), прошивка в этот момент ещё не запущена.

## Как детектируется короткое нажатие программно

Кнопка PWR физически подключена к пину `PWRON` чипа питания **AXP2101** (компонент `Key1` на схеме, см. `watch/res/ESP32-S3-Touch-AMOLED-2.06/Schematic/`). AXP2101 сам считает длительность нажатия и выставляет флаги в своих регистрах:

- `PKEY_SHORT_IRQ` — было короткое нажатие
- `PKEY_LONG_IRQ` — было длинное нажатие (на деле мы его почти не увидим: питание само обрежется раньше, чем успеем прочитать статус)

Отдельная GPIO-линия для кнопки не нужна — статус читается по тому же I2C, что и заряд батареи/VBUS.

### Код

- `components/sonya_board/pmu_xpowers.cpp`
  - `sonya_board_pmu_init()`: один раз при старте включает эти два IRQ: `s_pmu.enableIRQ(XPOWERS_AXP2101_PKEY_SHORT_IRQ | XPOWERS_AXP2101_PKEY_LONG_IRQ)`.
  - `sonya_board_pmu_poll_short_press()`: вызывается из главного цикла примерно раз в 100 мс. Делает `getIrqStatus()` (перечитывает регистры по I2C), проверяет `isPekeyShortPressIrq()`, при срабатывании сразу чистит статус (`clearIrqStatus()`), чтобы одно нажатие не поймалось дважды.
- `main/pwr_button.c` / `.h`
  - `pwr_button_tick(bool short_press_event)` — простой таймер двойного нажатия: помнит тик первого короткого нажатия, если второе пришло в пределах `PWR_BUTTON_DOUBLE_PRESS_WINDOW_MS` (600 мс) — возвращает `true` и сбрасывает состояние. Одно изолированное нажатие ничего не делает (кроме как запоминает себя на случай, если за ним придёт второе).
- `main/app_main.c`, главный `for(;;)` цикл:
  ```c
  if (pwr_button_tick(sonya_board_pmu_poll_short_press())) {
      watch_idle_off_force("BUTTON2X", s_is_recording, s_audio_streaming,
                           stop_audio_for_idle_off, NULL);
  }
  ```
- `main/watch_idle_off.c`: `watch_idle_off_force()` — тот же сценарий выключения, что и у обычного idle-off по таймеру (вибро/UI "OFF", отправка `POWEROFF:BUTTON` по BLE если был коннект, останов аудио, перевод BLE в power-save, `watch_power_enter_auto_off()`), но **без** ожидания 30-секундного таймера. Защиты те же, что у обычного авто-выключения:
  - если идёт запись (`recording`) — выключение игнорируется;
  - если на часах живой USB/VBUS — выключение блокируется, на экране мигает `USB` (отладка/зарядка не должна внезапно обрываться).

## Частые грабли при тестах

- **USB-кабель подключён → "нажал, ничего не произошло".** Это ожидаемо: `watch_idle_off_force()` сознательно отказывается выключать питание, пока видит VBUS (чтобы не вырубаться во время прошивки/логов/зарядки). На экране должно мелькнуть `USB` на 700 мс — если его не видно, возможно сам факт детекции нажатия и не произошёл (см. ниже).
  Проверить это за секунду: `watch_power_usb_present()` /в логе строка `forced power-off blocked by live USB/VBUS (BUTTON2X)`.
- **Хотите убедиться, что детекция самого нажатия (а не только блокировка по USB) реально работает** — слушайте serial живым логом во время нажатия:
  ```bash
  python3 - <<'EOF'
  import serial, time
  s = serial.Serial('/dev/ttyACM0', 115200, timeout=0.2)
  end = time.time() + 30
  while time.time() < end:
      line = s.readline()
      if line:
          print(line.decode(errors='replace').rstrip())
  EOF
  ```
  Ищите `pwr_button: double short press detected` и `watch_idle_off: forced power-off ...`.
- **Слишком медленный двойной клик** (>600 мс между нажатиями) не засчитается — каждое нажатие в отдельности для таймера "первое нажатие ещё не было" и ничего не произойдёт, кроме как сам факт запомнится как потенциальное первое нажатие новой пары.

## Диагностика на будущее (если IRQ вдруг "перестанет" ловиться)

Если понадобится ещё раз убедиться, что PMU физически видит нажатие (а не только что код выше написан правильно), можно временно добавить в `sonya_board_pmu_poll_short_press()` сырое чтение регистра статуса прерываний напрямую по I2C (минуя кэш библиотеки `XPowersLib`):

```c
uint8_t raw_intsts2 = 0;
pmu_register_read(AXP2101_ADDR, 0x49 /* XPOWERS_AXP2101_INTSTS2 */, &raw_intsts2, 1);
ESP_LOGW(TAG, "raw INTSTS2=0x%02X", raw_intsts2);
```

Бит короткого нажатия — `bit3` (`0x08`) этого регистра; бит длинного — `bit2` (`0x04`). Если бит никогда не появляется ни разу за несколько нажатий — проверять `INTEN2` (адрес `0x41`) сразу после `enableIRQ()`, чтобы убедиться, что включение IRQ реально записалось в чип.

Такой временный дебаг уже использовался 2026-10-08 для диагностики этой самой фичи — IRQ оказался рабочим с первого нажатия, просто тест проводился при подключённом USB (см. выше).
