## Кнопка записи / REC

Текущий режим прошивки: `CONFIG_WAKE_MODE_BUTTON=y`, кнопка на `GPIO0`, active-low.

Нормальный лог после нажатия верхней кнопки:

```text
wake trigger: BUTTON
REC_START
REC_END bytes=...
REC_END meta send rc=0
```

Если на телефоне не растут `bytes`, сначала смотреть serial-лог часов. Если нет `wake trigger` / `REC_START`, проблема до телефона: кнопка/GPIO/режим wake. Если `REC_END meta send rc=0` есть, часы запись сделали и отправили meta в BLE.

Важная ловушка: BLE-команда `REC` из телефона не должна молча игнорироваться в `BUTTON`-режиме. В `components/wake/wake.c` `wake_on_rx_cmd("REC")` должен выставлять `WAKE_SRC_CMD` и `s_wake_pending=true` не только в `WAKE_MODE_CMD`. В `main/app_main.c` нужно различать `by_btn`: физическая кнопка идет через `record_button()` (hold-to-record), BLE `REC` идет через `record_cmd()`.

## Если `idf.py` не находится

```bash
source /home/lapitsky/esp/esp-idf-5.4.2/export.sh
which idf.py
```

Опционально, чтобы всегда подхватывалось:

```bash
echo 'source /home/lapitsky/esp/esp-idf-5.4.2/export.sh >/dev/null 2>&1' >> ~/.bashrc
```
